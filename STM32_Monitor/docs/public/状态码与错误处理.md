# 状态码与错误处理

项目在 `Middlewares/error_code.h` 中集中维护主要状态码，按 App、Drivers、Middlewares、BSP 分层定义。各业务模块返回本层状态码，上层任务根据返回值记录日志、更新快照状态或触发重试。

每个枚举都从 `0` 开始，`*_OK` 表示成功，后续枚举值表示该模块内部的具体错误原因。因此排查日志时应同时查看状态码名称和括号中的数值。

## 状态码分层

| 层级 | 代表文件 | 职责 |
| --- | --- | --- |
| App | `App/app_sensor.c`、`App/app_scan.c`、`App/app_display.c`、`App/app_upload.c`、`App/app_ota_download.c`、`App/app_task.c` | 面向业务流程，负责传感器汇总、扫描、显示、上传、应用侧 OTA 和 FreeRTOS 任务协调 |
| Drivers | `Drivers/dht11.c`、`Drivers/amg8833.c`、`Drivers/oled.c`、`Drivers/atk_esp01.c`、`Drivers/encoder.c` | 面向具体器件，负责传感器、OLED、ESP01、舵机和编码器等设备驱动 |
| Middlewares | `Middlewares/at_parser.c`、`Middlewares/ring_buffer.c` | 提供 AT 指令解析、环形缓冲等通用能力 |
| BSP | `BSP/bsp_i2c.c`、`BSP/bsp_usart.c`、`BSP/bsp_adc.c`、`BSP/bsp_timer.c`、`BSP/bsp_pwm.c` | 封装 MCU 外设初始化、通信、超时和底层资源访问 |

## 命名规则

状态码命名采用 `模块_结果` 的形式：

- 成功状态统一为 `*_OK`。
- 参数问题通常使用 `*_ERROR_PARAM`。
- 初始化失败通常使用 `*_ERROR_INIT` 或底层对应的 `*_ERROR_NOT_INIT`。
- 通信类问题按外设区分，例如 `*_ERROR_I2C`、`*_ERROR_USART`、`*_ERROR_TIMEOUT`。
- 上层模块不会直接暴露所有底层细节，通常会映射为本模块的业务错误，例如 `APP_SENSOR_ERROR_READ`、`APP_UPLOAD_ERROR_ATK_ESP01`。

## 错误传播示例

### 传感器读取

传感器读取失败通常从底层驱动返回具体原因，再由 App 层归一化为业务状态：

```text
BSP_I2C_ERROR_TIMEOUT / DHT11_ERROR_CHECKSUM / HCSR04_ERROR_TIMER
        ↓
Drivers 层返回具体器件状态
        ↓
AppSensor_Update() 返回 APP_SENSOR_ERROR_READ
        ↓
EnvTask / ManualTask 记录日志并更新快照状态
```

这类错误主要通过 `[SENSOR]`、`[ENV]`、`[MANUAL]` 日志观察。

### 上传链路

上传失败会经过协议打包、ESP01 驱动和 AT 解析器多级传播：

```text
BSP_USART_ERROR_TIMEOUT / AT_PARSER_ERROR_RESPONSE
        ↓
ATK_ESP01_ERROR_TIMEOUT / ATK_ESP01_ERROR_RESPONSE
        ↓
APP_UPLOAD_ERROR_ATK_ESP01
        ↓
UploadTask 记录失败并进入重连或下次发送周期
```

如果是数据格式问题，则更可能表现为 `APP_UPLOAD_ERROR_PROTOCOL`。

### 应用侧 OTA

服务端下发 OTA 命令后，上传任务只负责解析和投递请求，实际下载由 `OtaDownloadTask` 独占 ESP01 完成。失败原因会保存在 OTA 状态报告中，并随下一轮上传报文返回给 PC 端服务程序。

```text
PATH/VER OTA command
        ↓
UploadTask 解析并投递 AppOtaDownload_Request_t
        ↓
OtaDownloadTask 独占 ESP01 并执行 HTTP 下载
        ↓
APP_OTA_DOWNLOAD_ERR_HTTP / ERR_FLASH / ERR_VERIFY / ERR_VERSION
        ↓
UploadTask 上报 OTA_LAST 和 OTA_DL_STATUS
```

### I2C 共享访问

OLED 和 AMG8833 共用 I2C 总线，任务层通过互斥量保护访问。互斥量失败不会被当作普通 I2C 通信错误处理，而是记录为 `APP_TASK_ERROR_MUTEX_TAKE` 或 `APP_TASK_ERROR_MUTEX_GIVE`。

```text
DisplayTask / EnvTask / ManualTask
        ↓
AppTask_TakeI2CMutex()
        ↓
APP_TASK_ERROR_MUTEX_TAKE
```
