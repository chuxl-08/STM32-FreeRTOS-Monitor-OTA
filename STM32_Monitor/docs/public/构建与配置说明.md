# 构建与配置说明

## 工程入口

项目以 Keil MDK 工程作为正式构建与上板验证入口：

```text
project.uvprojx
```

## 开发环境

| 项目 | 说明 |
| --- | --- |
| MCU | STM32F103ZE |
| 工程 | Keil MDK |
| 外设库 | STM32F10x 标准外设库 |
| RTOS | FreeRTOS |
| 下载器 | ST-Link |
| 调试日志 | USART1，115200 bps |
| Wi-Fi 模块 | ESP01，AT 指令固件 |

## 构建步骤

1. 使用 Keil MDK 打开 `project.uvprojx`。
2. 选择需要构建的构建目标。
3. 编译工程。
4. 通过 ST-Link 下载到开发板。
5. 使用串口工具打开 USART1 日志，波特率设置为 115200。

启动后可通过串口观察启动、任务、上传和低活动相关日志。

当前 Keil target：

| Target | 用途 | App 基址 |
| --- | --- | --- |
| `Target 1` | 原始单应用调试目标 | `0x08000000` |
| `Monitor Slot A` | Bootloader A/B Slot A 应用 | `0x08008000` |
| `Monitor Slot B` | Bootloader A/B Slot B 应用 | `0x08038000` |

Slot A/B target 通过 `APP_VECTOR_BASE_ADDR` 设置 App 向量表基址，并引用 Bootloader 共享头文件和固件校验/Config 相关模块。

## 上传配置

ESP01 上传功能依赖本地 Wi-Fi 和 TCP 服务端配置。公开版本中 `App/app_upload_config.h` 使用占位值：

```c
#define APP_UPLOAD_WIFI_SSID                 "YOUR_WIFI_SSID"
#define APP_UPLOAD_WIFI_PASSWORD             "YOUR_WIFI_PASSWORD"
#define APP_UPLOAD_TCP_HOST                  "192.168.x.x"
#define APP_UPLOAD_TCP_PORT                  8080
```

上板运行前需要根据本地网络环境修改：

- `APP_UPLOAD_WIFI_SSID`：Wi-Fi 名称。
- `APP_UPLOAD_WIFI_PASSWORD`：Wi-Fi 密码。
- `APP_UPLOAD_TCP_HOST`：TCP 服务端 IP 地址。
- `APP_UPLOAD_TCP_PORT`：TCP 服务端端口。

配置错误不会影响本地传感器采集和 OLED 显示，但会导致 ESP01 入网、TCP 连接或上传失败。

## OTA 打包与触发

Slot A/B 构建后，可以在项目根目录打包 `.bin`：

```powershell
python .\Tools\firmware_pack.py --slot a --version 11 .\Objects\SlotA\monitor_slot_a.bin .\Objects\monitor_slot_a_full_v11.pkg
python .\Tools\firmware_pack.py --slot b --version 12 .\Objects\SlotB\monitor_slot_b.bin .\Objects\monitor_slot_b_full_v12.pkg
```

使用 `ota_trigger_server.py` 模拟 PC 端服务程序触发应用侧 OTA：

```powershell
python .\Tools\ota_trigger_server.py --root .\Objects --host 0.0.0.0 --port 8080 --ota-count 1 --ota-path /monitor_slot_b_full_v12.pkg --ota-version 12
```

服务端返回 `OTA=1;PATH=...;VER=...` 后，应用使用 `PATH` 下载包、用 `VER` 对比包头版本，但写入目标仍由应用根据 Bootloader Config 选择非活动槽位。

## 常用运行日志

项目通过 USART1 输出运行日志。常见日志前缀如下：

| 日志前缀 | 含义 |
| --- | --- |
| `[BOOT]` | 启动信息和复位原因。 |
| `[SYSTEM]` | 模式协调、模式切换和 ACK 状态。 |
| `[SCAN]` | 自动扫描任务初始化、更新和快照发布状态。 |
| `[MANUAL]` | 手动控制任务初始化、舵机控制和方向检测状态。 |
| `[DISPLAY]` | OLED 初始化、刷新和页面状态。 |
| `[UPLOAD]` | ESP01 初始化、重连和上传状态。 |
| `[OTA-DL]` | 应用侧 OTA 下载、Flash 写入、校验和 `PENDING_VERIFY` 保存状态。 |
| `[OTA]` | Bootloader Config 摘要和健康确认状态。 |
| `[RTOS]` | 任务栈水位和堆水位。 |
| `[MONITOR]` | 任务健康状态和 IWDG 喂狗状态。 |
| `[POWER]` | OLED 空闲降刷新和上传退避状态。 |

示例：

```text
[BOOT] Reset_reason=POR
[RTOS] SystemTask_stack=...
[POWER] display_idle refresh=1000 ms
[POWER] upload_backoff wifi=0 tcp=0 retry=3000 ms
```

## 常见问题

### 编译通过但 Wi-Fi 上传失败

优先检查 `App/app_upload_config.h` 是否已经从占位值改成本地 Wi-Fi 和 TCP 服务端配置。

同时确认：

- ESP01 供电稳定。
- ESP01 AT 固件波特率与 USART3 配置一致。
- TCP 服务端 IP 和端口可连接。

### OLED 或 AMG8833 I2C 异常

OLED 和 AMG8833 共用 I2C1。若出现 ACK 超时、BUSY 异常或显示失败，优先检查：

- PB6 / PB7 接线。
- 3.3 V 供电和 GND 共地。
- I2C 上拉是否合适。

代码中 I2C 访问通过任务层互斥锁保护，BSP 层也保留超时检测和软恢复逻辑。

### ESP01 无响应

优先检查：

- ESP01 是否为 AT 固件。
- USART3 TX/RX 是否交叉连接。
- PB10 / PB11 接线是否正确。
- 模块供电是否能承受 Wi-Fi 连接时的峰值电流。
- 串口波特率是否为 115200。

### 上传失败是否会影响本地显示

不会。`UploadTask` 独立维护 Wi-Fi/TCP 状态，网络异常时进入退避重连；本地采集、OLED 显示、模式切换和任务监控仍继续运行。
